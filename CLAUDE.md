## Architecture: read this first

**This is a multi-page app (MPA), not a single-page app.** Each URL is a separate HTML document with its own JS bundle. There is no client-side router.

```
Browser GET /about
  → FastAPI app/frontend.py           returns frontend/dist/about.html   (generated by build.js)
  → about.html loads                  /pages/about.js + /pages/about.css
  → src/pages/about.tsx               mountPage(App)
  → src/components/about/App.tsx      page root; fetches data from /api/...

Browser fetch /api/items
  → app/routers/items.py              HTTP layer (validation, status codes)
  → app/services/items.py             data / business logic
  ← JSON (camelCase)                  typed on the client by src/misc/CommonInt.ts
```

- **Navigation** is plain `<a href="/other-page">` (a full page load). Pass state between pages through the query string (`?id=...`) and read it with `new URLSearchParams(window.location.search)`. **Do not add `react-router`.**
- **Code shared between pages** (React, `misc/`, common components) is split into `dist/pages/chunks/` by esbuild automatically, so adding pages doesn't duplicate React.
- **Routing is automatic on both sides.** The build turns every `src/pages/<name>.tsx` into `dist/<name>.html`, and FastAPI serves `/<name>` → `dist/<name>.html`. Adding a page needs no backend change.

## Setup and commands

Requirements: **Node >= 26.5** (`frontend/.nvmrc`) and **Python >= 3.12**. `make` is optional; the raw commands are listed below.

```bash
make install    # npm install + create backend/.venv + pip install
make dev        # frontend watcher + backend autoreload → http://localhost:8000
make check      # typecheck + prettier check + ruff + pytest. RUN BEFORE EVERY PUSH.
make format     # prettier --write + ruff fix/format
make test       # backend tests only
make build      # minified production frontend build
make prod       # production stack in Docker → http://localhost:8000 (see "Production (Docker)")
make prod-logs  # follow container logs
make prod-down  # stop the production stack
make smoke      # read-only end-to-end check of a running app (URL=http://host:port to target another)
```

Raw equivalents (Windows, or when you only need one side):

```bash
# Frontend (from frontend/)
npm install
node build.js            # dev build into dist/
node build.js -w         # dev build + watch (rebuilds on save, picks up new/removed pages)
node build.js --prod     # minified build
npx tsc --noEmit         # typecheck. The build does NOT do this.
npx prettier --write .

# Backend (from backend/)
python3 -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
pytest -q
ruff check --fix . && ruff format .
```

- Interactive API docs: **http://localhost:8000/docs** (Swagger UI, generated by FastAPI).
- **No live reload in the browser.** After the watcher prints `[build] ...`, refresh the page.
- **`make dev` (or both processes) must be running.** The backend serves whatever is in `frontend/dist/`; if you never built, every page returns 404 "Has the frontend been built?".

## Recipes

### Add a page (2 files)

1. `frontend/src/components/<page>/App.tsx` is the page root. Wrap its content in `<Layout title="...">` from `../common/Layout`.
2. `frontend/src/pages/<page>.tsx`:
    ```tsx
    import App from "../components/<page>/App";
    import { mountPage } from "../misc/mountPage";

    mountPage(App);
    ```

That's it. The watcher picks it up and it's live at `/<page>`. Add it to `NAV_LINKS` in `components/common/Layout.tsx` if it belongs in the header.

- Page names: **lowercase kebab-case** (`order-history`), because they become the URL. `index` is `/`.
- **Reserved names:** `api`, `docs`, `redoc`, `openapi.json`, `pages`, `assets`, `static`. They collide with backend routes or static mounts.

### Add an API endpoint (touches 4 places)

Follow `items` as the template. For a new feature `widgets`:

1. **Types:** add `WidgetWHid` + `Widget` to `backend/app/schemas.py` **and** the matching interfaces to `frontend/src/misc/CommonInt.ts`.
2. **Service:** `backend/app/services/widgets.py` holds plain functions (`list_widgets`, `get_widget_by_id`, `create_widget`, ...). No FastAPI imports here. Return `None` / `False` for "not found"; don't raise HTTP errors.
3. **Router:** `backend/app/routers/widgets.py` uses `router = APIRouter(prefix="/widgets", tags=["widgets"])`. Handlers have **the same name as the service function they call**, call it via `from app.services import widgets as widgets_service`, and turn `None` into `HTTPException(404)`. Register the router in `backend/app/routers/__init__.py`.
4. **Client:** in `frontend/src/misc/apiClient.ts`, add `api` + the PascalCase handler name: `get_widget_by_id` → `apiGetWidgetById`.

Then add a test in `backend/tests/test_widgets.py`.

**The naming chain is the contract:** service `get_widget_by_id` = router handler `get_widget_by_id` = client `apiGetWidgetById`. Searching any one of them finds all three.

URL shape (REST):

| Action | Method + path | Handler | Success |
|---|---|---|---|
| list | `GET /api/widgets` | `list_widgets` | 200 |
| read | `GET /api/widgets/{widget_id}` | `get_widget_by_id` | 200 / 404 |
| create | `POST /api/widgets` (body `WidgetWHid`) | `create_widget` | 201 |
| update | `PATCH /api/widgets/{widget_id}` | `update_widget` | 200 / 404 |
| delete | `DELETE /api/widgets/{widget_id}` | `delete_widget` | 204 / 404 |

Non-CRUD actions are verbs under the resource: `POST /api/widgets/{widget_id}/publish` → `publish_widget`.

### Add a dependency

Ask the team first (in chat) for anything big. Then:
- Frontend: `cd frontend && npm install <pkg>` (commit `package.json` **and** `package-lock.json`).
- Backend: add it to `backend/requirements.txt` (or `-dev.txt`) with a `>=` lower bound, then `pip install -r requirements-dev.txt`.

### Removing the example

When the first real feature lands, delete `routers/items.py`, `services/items.py`, `tests/test_items.py`, `components/index/ItemCard.*`, `components/index/ItemForm.*`, the `Item*` types in `schemas.py` and `CommonInt.ts`, the `apiListItems/...` functions, and the items line in `routers/__init__.py`. Then rewrite `components/index/App.tsx`.

## Production (Docker)

Production runs as **one container**: the same FastAPI app as in dev, serving the API and a minified frontend build. Docker is for production and demos only; develop with `make dev`.

```bash
docker compose up --build -d     # or: make prod      → http://localhost:8000
docker compose logs -f           # or: make prod-logs
docker compose down              # or: make prod-down
APP_PORT=9000 docker compose up --build -d   # publish on another host port
```

How the image is built ([Dockerfile](Dockerfile)):

1. **Stage `frontend`** (`node:26-alpine`): `npm ci`, then `node build.js --prod` (minified, production React, no source maps).
2. **Runtime stage** (`python:3.14-slim`): installs **only** `backend/requirements.txt`, copies `backend/app/` and the built `frontend/dist/`, runs as a non-root user, and starts `uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1`.

Inside the image the paths mirror the repo (`/app/backend`, `/app/frontend/dist`), so `app/config.py` finds the frontend with no extra configuration.

- **Configuration:** `compose.yaml` loads `backend/.env` if it exists (optional) and always forces `ENVIRONMENT=production`. Put production secrets in that `.env` on the server, never in the image. `.dockerignore` keeps every `.env` out of the build context.
- **CD:** after CI passes on `main`, [.github/workflows/cd.yml](.github/workflows/cd.yml) pushes the image to `ghcr.io/<owner>/<repo>:latest` and `:<sha>`. When the repo variables `DEPLOY_HOST`/`DEPLOY_USER` (optional `DEPLOY_PORT`) and the secret `DEPLOY_SSH_KEY` are set, it also deploys over SSH using [compose.prod.yaml](compose.prod.yaml) (runs the published image, reads `~/app/.env` on the server) and smoke-tests the live URL. Roll back on the server with `IMAGE=ghcr.io/<owner>/<repo> TAG=<older sha> docker compose -f compose.prod.yaml up -d`.
- **Health:** the container has a `HEALTHCHECK` on `GET /api/health`; `docker compose ps` shows `healthy` once it is up. Keep that endpoint cheap and dependency-free.
- **Adding a runtime dependency** = add it to `backend/requirements.txt` (dev-only tools go in `requirements-dev.txt`, which the image does not install). Frontend deps are picked up from `package-lock.json` via `npm ci`, so commit the lockfile.
- **Adding a service** (database, cache, ...): add it to `compose.yaml`, give it a named volume for its data, pass its URL to `app` through `environment:`, and add a matching field to `Settings` in `app/config.py`.
- **New top-level backend folders** besides `app/` (e.g. `backend/data/`) are **not** copied into the image. Add a `COPY` line to the Dockerfile.

## Types and data contract

- **Single source per side:** every API/domain type lives in `backend/app/schemas.py` (Pydantic) and `frontend/src/misc/CommonInt.ts` (TS). Don't scatter `interface`s for API data across components. Component-only types (props) stay next to the component.
- **`WHid` = "without id".** `XWHid` is the create payload the client sends; `X` (Python: `class X(XWHid)`, TS: `interface X extends XWHid`) adds `id` and timestamps. Partial-update payloads are named `XUpdate` with all-optional fields.
- **Casing on the wire is camelCase.** Every Pydantic schema extends `CamelModel`, so Python `created_at` is serialized as `createdAt`. Write snake_case in Python and camelCase in TS; never hand-convert.
- **IDs** are `uuid4().hex` strings, generated in the service layer. **Datetimes** are timezone-aware UTC (`datetime.now(UTC)`), sent as ISO 8601 strings and typed `string` in TS.
- **API results** on the client are always `ApiResult<T> = { data, status, error }`. `status` is 0 when the network failed. API functions never throw, so check `error`.

## Conventions

### General
- **English** for all identifiers, comments, commits and UI copy (unless the product needs otherwise).
- Comments explain **why**, not what. Keep a one-line module docstring/comment at the top of non-obvious files.
- Don't commit `dist/`, `.venv/`, `.env`, or `node_modules/`.

### Frontend (TypeScript / React)
- **Components:** `export default function Foo(args: FooArgs)`, i.e. a function declaration with a default export. **One component per file**, and the filename equals the component name (`ItemCard.tsx`).
- **The props parameter is named `args`, not `props`**, and is not destructured in the signature (`args.item.title`). Props are typed by an `interface <Component>Args` declared **directly above** the component. Components with no props take no parameter.
- **Don't** write `const Foo: React.FC<Props> = (...) =>`.
- **Page roots** are always `components/<page>/App.tsx`, named `App`.
- **Utilities and hooks** (`misc/`) use **named exports** (`export function useApi`). Hooks start with `use`.
- **Event handlers** inside components are `function handleX()`; callback props are `onX` (`onDelete`, `onSubmit`).
- **Naming:** `PascalCase` components/types/interfaces, `camelCase` variables/functions, `UPPER_SNAKE_CASE` module-level constants. Booleans read as questions (`isOpen`, `hasError`, `submitting`).
- **`const` by default, `let` when reassigned, never `var`.**
- **Imports:** relative paths, **no file extensions**, no path aliases. Use `import type { ... }` for type-only imports (`verbatimModuleSyntax` enforces it). Order: react → other packages → local components → misc → types → styles (last).
- **State:** no global store. `useState` in the page `App`, passed down as props. If prop drilling gets painful (3+ levels), discuss a React context with the team before adding a library.
- **Data fetching:** `useApi(apiSomething)` for reads, or `useApi(() => apiGetXById(id), [id])` when it has parameters. Call `api*` functions directly for mutations, then `reload()` the affected `useApi`. Never fetch at module scope and never call `fetch` directly from a component. Go through `apiClient.ts`.
- **Styling:** CSS Modules, co-located, same basename (`ItemCard.tsx` ↔ `ItemCard.module.css`), **camelCase class names** (`styles.deleteButton`). Use the CSS variables from `styles/global.css` (`var(--space-3)`, `var(--color-primary)`) instead of hard-coding colors and spacing. Use conditional rendering (`{cond && <X/>}`) to show and hide things. No inline `style={{}}` except for truly dynamic values.
- **Assets:** images imported in code (`import logoUrl from "./logo.png"`) are hashed into `dist/assets/`. Files that need a stable URL go in `frontend/public/` and are served at `/static/<file>`.
- **Formatting:** Prettier with **4-space indent and semicolons** (`.prettierrc`); everything else is Prettier defaults. Don't hand-format; run `make format`.

### Backend (Python / FastAPI)
- **PEP 8 naming:** `snake_case` functions/variables/modules, `PascalCase` classes, `UPPER_SNAKE_CASE` constants. The `XWHid` class names are an intentional exception (allowed in ruff config).
- **Type-hint every function** signature. Annotate route handlers with their return type (`-> Item`, `-> list[Item]`). FastAPI uses it as the response model, so no `response_model=` is needed.
- **Layering:** routers handle HTTP (status codes, `HTTPException`, request parsing); services handle data and logic, with no FastAPI imports and no knowledge of HTTP. Routers never touch storage directly.
- **One router module + one service module per feature**, same filename (`routers/widgets.py` ↔ `services/widgets.py`).
- **`def` vs `async def`:** use plain `def` unless the handler actually `await`s something (async HTTP client, async DB driver). FastAPI runs `def` handlers in a threadpool; a blocking call inside `async def` freezes the whole server.
- **Errors:** raise `HTTPException(status.HTTP_404_NOT_FOUND, "Widget not found")` with the named `status` constants and a human-readable `detail`. The frontend shows `detail` as the error message.
- **Validation** lives in the schema (`Field(min_length=1, max_length=200)`), not in handler `if`s.
- **Config:** add new settings as fields on `Settings` in `app/config.py` and document them in `.env.example`. Read them via `from app.config import settings`. Never use `os.environ` directly, and never commit secrets.
- **Imports:** absolute from the package root (`from app.schemas import Item`). Ruff sorts them.
- **Tests:** `tests/test_<feature>.py`, functions `test_<behaviour>`, using the `client` fixture and asserting on the JSON (camelCase) the frontend actually sees.
- **Formatting/linting:** `ruff format` + `ruff check` (line length 100). Run `make format`.

## Team workflow

The full rules are in [docs/BRANCH_RULES.md](docs/BRANCH_RULES.md) (humans) and [AGENTS.md](AGENTS.md) (agents, stricter). In short:

- **`main` must always run.** Never push straight to `main`; every change is a PR, squash-merged.
- **Branches:** `<type>/<issue>-<slug>`, e.g. `feat/14-upload-page` (types: `feat`, `fix`, `chore`, `docs`, `pitch`). Keep them small and short-lived (hours, not days). Merge `origin/main` into your branch at least hourly.
- **Commits and PR titles:** `<type>: <what it does> (#<issue>)`, e.g. `feat: add upload endpoint (#12)`. The PR title becomes the commit on `main`.
- **Before pushing:** `make check` must pass, plus `make prod && make smoke` for runtime/deployment changes. CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) runs the same checks plus the production build and Docker smoke test on every PR; don't merge until all four checks are green.
- **Day-to-day flow, labels and issue/PR templates:** [CONTRIBUTING.md](CONTRIBUTING.md). Record decisions in [docs/DECISIONS.md](docs/DECISIONS.md).
- **Hot files** (`CommonInt.ts`, `schemas.py`, `apiClient.ts`, `routers/__init__.py`, `Layout.tsx`) are edited by everyone. Keep edits there **append-only, grouped under a `# --- <feature> ---` / `// --- <feature> ---` header**, and pull before editing to keep merge conflicts trivial.
- **Splitting work:** one person per feature end to end (schema → service → router → client → UI) works better than frontend/backend splits. Agree on the `schemas.py`/`CommonInt.ts` shapes first, push them, then build both sides in parallel.

## Gotchas

- **The frontend build does not typecheck.** esbuild strips types without checking them. Run `npx tsc --noEmit` (included in `make check`).
- **The example data store is in memory.** `uvicorn --reload` restarts the process on every Python save, which wipes all data. The same happens in production on every container restart or redeploy. Expected until a real database replaces the dict in `services/`.
- **The production container runs one uvicorn worker on purpose.** In-memory state is per process, so with `--workers 2` each request could hit a different copy of the data. Only raise it once state lives in a database.
- **`/docs` (Swagger UI) is also exposed in production.** That's handy for a demo, but if the API should be private, pass `docs_url=None, redoc_url=None, openapi_url=None` to `FastAPI(...)` when `settings.environment == "production"`.
- **You must refresh the browser** after a rebuild (no HMR). Responses are sent `Cache-Control: no-cache`, so a normal refresh is enough.
- **`/{page_name}` is a catch-all** for single-segment paths. `mount_frontend(app)` must stay the **last** line in `main.py`, after every router.
- **The page bundle is `type="module"`**, so top-level code runs after the DOM is parsed and `import`s are real ES modules. Don't use `require`.
- **`StrictMode` double-invokes effects in development.** Effects must be idempotent; `useApi` already handles cancellation.
- Pages deleted from `src/pages/` are removed from `dist/` on the next rebuild. If the watcher acts strangely after big file moves, restart it (it wipes `dist/` on startup).
