## What this is

**ETH Life** (working title), our VIScon 2026 game. You create an ETH student (name, pronouns, department, archetype, avatar), play two minigames, and your scores decide your career at graduation: C-level executive, big-tech engineer, eternal PhD, McDonald's or unemployed. The minigames are **Blackjack** ("Casino night") and a **webcam finger-gun shooter** ("Basisprüfung"): you aim with your index finger and drop your thumb to shoot, tracked live in the browser. The shooter is the feature we win with. OpenAI writes the story around your character: advisor and dealer lines, a personal epilogue, and a narrator voice.

**The demo flow that must work on judging day:** enroll → campus → blackjack → shooter with the camera → graduation reveal, read aloud.

Anything marked *(planned)* below does not exist until its PR lands ([build status](docs/ARCHITECTURE.md#build-status)).

Stack: **React + TypeScript** outer shell bundled by **esbuild**; a WebGL inner shell for the minigames: **Phaser 4** for both (blackjack, and the shooter, which fakes depth with isometric 2D art); **MediaPipe** hand tracking in the browser; a **FastAPI** backend with **Redis** (no Redux, no client-side store); and **OpenAI** called only from the backend. FastAPI serves both the JSON API and the built frontend from **one origin**, so there is no CORS, no proxy and no API base URL.

## Architecture: read this first

**This is a multi-page app (MPA), not a single-page app.** Each URL is a separate HTML document with its own JS bundle, and each game scene is its own page: `/`, `/enroll`, `/campus`, `/blackjack`, `/shooter`, `/graduation`. There is no client-side router.

```
Browser GET /blackjack?run=abc
  → FastAPI app/frontend.py           returns frontend/dist/blackjack.html   (generated by build.js)
  → blackjack.html loads              /pages/blackjack.js (incl. Phaser) + shared chunks (React, misc/)
  → src/pages/blackjack.tsx           mountPage(App)
  → src/components/blackjack/App.tsx  React outer shell: intro, MinigameHost, result screen, navigation
  → level2/index.ts                   mountBlackjack(): Phaser 4 inner shell (2D, WebGL canvas),
                                      registered in src/games/registry.ts
  (/shooter works the same way: games/shooter/index.ts mountShooter() = Phaser isometric scene + MediaPipe)

Browser fetch POST /api/runs/abc/scores
  → app/routers/runs.py               HTTP layer (validation, status codes)
  → app/services/runs.py              business logic
  → app/db.py → Redis                 storage
  ← JSON (camelCase)                  typed on the client by src/misc/CommonInt.ts

Story endpoints: app/routers/story.py → app/services/story.py → app/ai.py → OpenAI (keys only on the server)
```

- **Navigation** is plain `<a href="/other-page">` or `window.location.href` (a full page load). Pass state between pages through the query string: the run id is `?run=<id>`, built and read only through `misc/run.ts`. **Do not add `react-router`.**
- **Two shells, one seam.** React owns everything around a round (menus, character creator, hub, overlays, saving, navigation). Phaser 4 owns the round itself, in both minigames. They meet only through the `MountMinigame` contract in `games/shared/minigame.ts`. Pages never import Phaser; `games/` never fetches, never navigates and never imports React.
- **Blackjack is level 2.** A minigame's own code lives in a level folder: `frontend/level2/` holds the game (rules, scene, sprite sheets) and `backend/level2/` its server side (the dealer's dialogue, with its own `tests/`). A level touches the shell only through hooks: its mount function in `src/games/registry.ts`, `level2` in `frontend/tsconfig.json`, the imports in `app/prompts.py` and `app/services/fallbacks.py`, `level2/tests` in `backend/pyproject.toml`, and `COPY backend/level2` in the Dockerfile.
- **No client-side store (no Redux).** Every navigation is a full page load, which wipes in-memory state. The character and the run live on the server; each page loads them through the API.
- **Computer vision runs in the browser.** MediaPipe tracks the hand on the device; video frames never reach the backend. Details in [docs/SHOOTER_CV.md](docs/SHOOTER_CV.md).
- **Secrets stay on the server.** Only `backend/app/ai.py` talks to OpenAI.
- **Code shared between pages** (React, `misc/`, common components) is split into `dist/pages/chunks/` by esbuild automatically. Phaser is imported only by the two game pages, so esbuild puts it in one shared chunk that `/blackjack` and `/shooter` reuse from the cache, and only `/shooter` downloads MediaPipe.
- **Routing is automatic on both sides.** The build turns every `src/pages/<name>.tsx` into `dist/<name>.html`, and FastAPI serves `/<name>` → `dist/<name>.html`. Adding a page needs no backend change.

## Setup and commands

Requirements: **Node >= 26.5** (`frontend/.nvmrc`; run `nvm install` in `frontend/`, since some laptops still have Node 24) and **Python >= 3.12**. `make` is optional; the raw commands are listed below.

```bash
make install    # npm install + create backend/.venv + pip install
make dev        # frontend watcher + backend autoreload → http://localhost:8000
make check      # typecheck + prettier check + ruff + pytest. RUN BEFORE EVERY PUSH.
make format     # prettier --write + ruff fix/format
make test       # backend tests only
make build      # minified production frontend build
make prod       # production stack in Docker → http://localhost:8000 (see "Production (Docker)")
make prod-logs  # follow container logs
make prod-down  # stop the production stack
make smoke      # read-only end-to-end check of a running app (URL=http://host:port to target another)

make redis      # optional: a real Redis on 127.0.0.1:6379 (dev works without it, see "Gotchas")
make ai-check   # verify every OpenAI key and model; free (LIVE=1 adds a 16-token call per key)

# planned
make art        # generate art and fallback narration offline. SPENDS CREDITS; asks first
```

Raw equivalents (Windows, or when you only need one side):

```bash
# Frontend (from frontend/)
npm install
node build.js            # dev build into dist/
node build.js -w         # dev build + watch (rebuilds on save, picks up new/removed pages)
node build.js --prod     # minified build
npx tsc --noEmit         # typecheck. The build does NOT do this.
npx prettier --write .

# Backend (from backend/)
python3 -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
pytest -q
ruff check --fix . && ruff format .
```

- Interactive API docs: **http://localhost:8000/docs** (Swagger UI, generated by FastAPI).
- **No live reload in the browser.** After the watcher prints `[build] ...`, refresh the page.
- **`make dev` (or both processes) must be running.** The backend serves whatever is in `frontend/dist/`; if you never built, every page returns 404 "Has the frontend been built?".
- **`make dev` never spends OpenAI credits:** `AI_MODE` defaults to `off`. See "OpenAI" under Conventions.

## Recipes

### Add a page (2 files)

1. `frontend/src/components/<page>/App.tsx` is the page root. Wrap its content in `<Layout title="...">` from `../common/Layout`.
2. `frontend/src/pages/<page>.tsx`:
    ```tsx
    import App from "../components/<page>/App";
    import { mountPage } from "../misc/mountPage";

    mountPage(App);
    ```

That's it. The watcher picks it up and it's live at `/<page>`. Add it to `NAV_LINKS` in `components/common/Layout.tsx` if it belongs in the header.

- Page names: **lowercase kebab-case** (`order-history`), because they become the URL. `index` is `/`.
- **Reserved names:** `api`, `docs`, `redoc`, `openapi.json`, `pages`, `assets`, `static`. They collide with backend routes or static mounts.

### Add an API endpoint (touches 4 places)

The real contract is in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#api-contract); add new endpoints to its table in the same PR. For a new feature `widgets`:

1. **Types:** add `WidgetWHid` + `Widget` to `backend/app/schemas.py` **and** the matching interfaces to `frontend/src/misc/CommonInt.ts`.
2. **Service:** `backend/app/services/widgets.py` holds plain functions (`list_widgets`, `get_widget_by_id`, `create_widget`, ...). No FastAPI imports here. Return `None` / `False` for "not found"; don't raise HTTP errors (raise a small domain error for conflicts, and let the router map it to 409).
3. **Router:** `backend/app/routers/widgets.py` uses `router = APIRouter(prefix="/widgets", tags=["widgets"])`. Handlers have **the same name as the service function they call**, call it via `from app.services import widgets as widgets_service`, and turn `None` into `HTTPException(404)`. Register the router in `backend/app/routers/__init__.py`.
4. **Client:** in `frontend/src/misc/apiClient.ts`, add `api` + the PascalCase handler name: `get_widget_by_id` → `apiGetWidgetById`.

Then add a test in `backend/tests/test_widgets.py`.

**The naming chain is the contract:** service `get_widget_by_id` = router handler `get_widget_by_id` = client `apiGetWidgetById`. Searching any one of them finds all three.

URL shape (REST):

| Action | Method + path | Handler | Success |
|---|---|---|---|
| list | `GET /api/widgets` | `list_widgets` | 200 |
| read | `GET /api/widgets/{widget_id}` | `get_widget_by_id` | 200 / 404 |
| create | `POST /api/widgets` (body `WidgetWHid`) | `create_widget` | 201 |
| update | `PATCH /api/widgets/{widget_id}` | `update_widget` | 200 / 404 |
| delete | `DELETE /api/widgets/{widget_id}` | `delete_widget` | 204 / 404 |

Non-CRUD actions are verbs under the resource: `POST /api/widgets/{widget_id}/publish` → `publish_widget`.

### Add a minigame

1. **Game:** `frontend/src/games/<game>/index.ts` exports `mount<Game>: MountMinigame` (see `games/shared/minigame.ts`). Use Phaser through `games/shared/createGame.ts`; fake depth with isometric art instead of a 3D engine. Scenes, `config.ts` and `assets/` sit next to it. Logic that can be pure (rules, scoring) goes into plain `.ts` files with unit tests.
2. **Page:** `components/<game>/App.tsx` renders the intro, then `<MinigameHost mount={mount<Game>} ... />`, then the result screen; on finish it calls `apiSubmitScore` and returns to `/campus`. Add `pages/<game>.tsx` as in "Add a page".
3. **Contract:** add the id to `GameId` in `schemas.py` and `CommonInt.ts`. The ending uses the average of all games; update `services/endings.py` and its tests if the rules change.
4. **Story:** add a `DialogueScene` and its event keys in `app/prompts.py` and `services/fallbacks.py`, and list the keys in GAME_DESIGN.md.
5. **Hub:** add an activity card on `/campus`.

### Add an AI-backed endpoint

1. **Fallback first:** write the pre-written content in `services/fallbacks.py`. The endpoint must work in `AI_MODE=off`.
2. **Prompt:** text and output schema go in `app/prompts.py`. Pass player data as data, cap the output length.
3. **Service:** call a helper from `app/ai.py` (never `openai` directly); cache the result in Redis per run (and scene/stage); return `source: "ai"` or `"fallback"`.
4. **Router:** `POST` only (GET must never spend credits); answer 200 with fallback content rather than 5xx when the AI fails.
5. **Tests:** use `FakeAI`; cover success, AI failure → fallback, and "a second call hits the cache". Tests never reach the network.
6. **Docs:** add the endpoint and any new Redis key to [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

### Add a dependency

Ask the team first (in chat) for anything big. Then:
- Frontend: `cd frontend && npm install <pkg>` (commit `package.json` **and** `package-lock.json`).
- Backend: add it to `backend/requirements.txt` (or `-dev.txt`) with a `>=` lower bound, then `pip install -r requirements-dev.txt`.

The planned additions and their versions are listed in [docs/STACK.md](docs/STACK.md).

## Production (Docker)

Production runs as **the app container plus Redis**: the same FastAPI app as in dev, serving the API and a minified frontend build. Docker is for production and demos only; develop with `make dev`.

```bash
docker compose up --build -d     # or: make prod      → http://localhost:8000
docker compose logs -f           # or: make prod-logs
docker compose down              # or: make prod-down
APP_PORT=9000 docker compose up --build -d   # publish on another host port
```

How the image is built ([Dockerfile](Dockerfile)):

1. **Stage `frontend`** (`node:26-alpine`): `npm ci`, then `node build.js --prod` (minified, production React, no source maps).
2. **Runtime stage** (`python:3.14-slim`): installs **only** `backend/requirements.txt`, copies `backend/app/`, `backend/level2/` and the built `frontend/dist/`, runs as a non-root user, and starts `uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1`.

Both base images are pulled from `public.ecr.aws/docker/library/`, AWS's mirror of the Docker Official Images (same digests as Docker Hub), because Docker Hub rate-limits anonymous pulls per IP and shared IPs (CI runners, the event network) hit that limit. Use the same prefix for any new service image, e.g. `public.ecr.aws/docker/library/redis:8-alpine`, and don't add a `# syntax=` line to the Dockerfile (it pulls from Docker Hub).

Inside the image the paths mirror the repo (`/app/backend`, `/app/frontend/dist`), so `app/config.py` finds the frontend with no extra configuration.

- **Configuration:** `compose.yaml` loads `backend/.env` if it exists (optional) and always forces `ENVIRONMENT=production`. Put production secrets in that `.env` on the server, never in the image. `.dockerignore` keeps every `.env` out of the build context.
- **OpenAI keys:** on the VM they live in the server `.env` (`~/app/.env` with CD, `backend/.env` in a manual clone) as `OPENAI_API_KEYS` with `AI_MODE=live`, never in GitHub. CD doesn't need them. Full rules: [ARCHITECTURE.md → Where the API keys live](docs/ARCHITECTURE.md#where-the-api-keys-live).
- **Redis**: service `redis` (`public.ecr.aws/docker/library/redis:8-alpine`, AOF on, named volume `redis-data`), reachable only inside the Compose network. **Never add a `ports:` entry for it.** `app` gets `REDIS_URL=redis://redis:6379/0`.
- **Camera:** the shooter needs a secure origin (HTTPS or `localhost`). Options in [ARCHITECTURE.md → Deployment](docs/ARCHITECTURE.md#deployment).
- **CD:** after CI passes on `main`, [.github/workflows/cd.yml](.github/workflows/cd.yml) pushes the image to `ghcr.io/<owner>/<repo>:latest` and `:<sha>`. When the repo variables `DEPLOY_HOST`/`DEPLOY_USER` (optional `DEPLOY_PORT`) and the secret `DEPLOY_SSH_KEY` are set, it also deploys over SSH using [compose.prod.yaml](compose.prod.yaml) (runs the published image, reads `~/app/.env` on the server) and smoke-tests the live URL. Roll back on the server with `IMAGE=ghcr.io/<owner>/<repo> TAG=<older sha> docker compose -f compose.prod.yaml up -d`.
- **Health:** the container has a `HEALTHCHECK` on `GET /api/health`; `docker compose ps` shows `healthy` once it is up. Keep that endpoint cheap and dependency-free (it must not touch Redis or OpenAI).
- **Adding a runtime dependency** = add it to `backend/requirements.txt` (dev-only tools go in `requirements-dev.txt`, which the image does not install). Frontend deps are picked up from `package-lock.json` via `npm ci`, so commit the lockfile.
- **Adding a service** (database, cache, ...): add it to `compose.yaml`, give it a named volume for its data, pass its URL to `app` through `environment:`, and add a matching field to `Settings` in `app/config.py`.
- **New top-level backend folders** besides `app/` (e.g. `backend/tools/`) are **not** copied into the image. Add a `COPY` line to the Dockerfile if the running app needs them.

## Types and data contract

- **The contract** (every type and endpoint) is written down in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#api-contract). Agree on changes there first.
- **Single source per side:** every API/domain type lives in `backend/app/schemas.py` (Pydantic) and `frontend/src/misc/CommonInt.ts` (TS). Don't scatter `interface`s for API data across components. Component-only types (props) stay next to the component.
- **`WHid` = "without id".** `XWHid` is the create payload the client sends; `X` (Python: `class X(XWHid)`, TS: `interface X extends XWHid`) adds `id` and timestamps. Partial-update payloads are named `XUpdate` with all-optional fields.
- **Enumerations** (`GameId`, `EndingId`, `DepartmentId`, ...) are string unions in TS and `Literal[...]` in Python, with identical values.
- **Casing on the wire is camelCase.** Every Pydantic schema extends `CamelModel`, so Python `created_at` is serialized as `createdAt`. Write snake_case in Python and camelCase in TS; never hand-convert. (Dictionary *keys* such as game ids are data and are not converted.)
- **IDs** are `uuid4().hex` strings, generated in the service layer. **Datetimes** are timezone-aware UTC (`datetime.now(UTC)`), sent as ISO 8601 strings and typed `string` in TS.
- **API results** on the client are always `ApiResult<T> = { data, status, error }`. `status` is 0 when the network failed. API functions never throw, so check `error`.

## Conventions

### General
- **English** for all identifiers, comments, commits and UI copy (unless the product needs otherwise).
- Comments explain **why**, not what. Keep a one-line module docstring/comment at the top of non-obvious files.
- Don't commit `dist/`, `.venv/`, `.env`, `node_modules/`, or `frontend/public/models/`.

### Frontend (TypeScript / React)
- **Components:** `export default function Foo(args: FooArgs)`, i.e. a function declaration with a default export. **One component per file**, and the filename equals the component name (`ItemCard.tsx`).
- **The props parameter is named `args`, not `props`**, and is not destructured in the signature (`args.item.title`). Props are typed by an `interface <Component>Args` declared **directly above** the component. Components with no props take no parameter.
- **Don't** write `const Foo: React.FC<Props> = (...) =>`.
- **Page roots** are always `components/<page>/App.tsx`, named `App`.
- **Utilities and hooks** (`misc/`) use **named exports** (`export function useApi`). Hooks start with `use`.
- **Event handlers** inside components are `function handleX()`; callback props are `onX` (`onDelete`, `onSubmit`).
- **Naming:** `PascalCase` components/types/interfaces, `camelCase` variables/functions, `UPPER_SNAKE_CASE` module-level constants. Booleans read as questions (`isOpen`, `hasError`, `submitting`).
- **`const` by default, `let` when reassigned, never `var`.**
- **Imports:** relative paths, **no file extensions**, no path aliases. Use `import type { ... }` for type-only imports (`verbatimModuleSyntax` enforces it). Order: react → other packages → local components → misc → types → styles (last).
- **State:** no global store, and no Redux: a full page load would wipe it anyway. `useState` in the page `App`, passed down as props; anything that must survive navigation lives on the server and travels as `?run=`. If prop drilling gets painful (3+ levels), discuss a React context with the team before adding a library.
- **Data fetching:** `useApi(apiSomething)` for reads, or `useApi(() => apiGetXById(id), [id])` when it has parameters. Call `api*` functions directly for mutations, then `reload()` the affected `useApi`. Never fetch at module scope and never call `fetch` directly from a component. Go through `apiClient.ts`.
- **Styling:** CSS Modules, co-located, same basename (`ItemCard.tsx` ↔ `ItemCard.module.css`), **camelCase class names** (`styles.deleteButton`). Use the CSS variables from `styles/global.css` (`var(--space-3)`, `var(--color-primary)`) instead of hard-coding colors and spacing. Use conditional rendering (`{cond && <X/>}`) to show and hide things. No inline `style={{}}` except for truly dynamic values.
- **Assets:** images imported in code (`import logoUrl from "./logo.png"`) are hashed into `dist/assets/`. Files that need a stable URL go in `frontend/public/` and are served at `/static/<file>`.
- **Formatting:** Prettier with **4-space indent and semicolons** (`.prettierrc`); everything else is Prettier defaults. Don't hand-format; run `make format`.

### Game code (`frontend/src/games/`, Phaser)
- **One folder per minigame, one engine for all: Phaser 4.** Blackjack is plain 2D; the shooter fakes depth with isometric art (see [docs/SHOOTER_CV.md](docs/SHOOTER_CV.md)). No 3D engine. `index.ts` exports only the mount function (`mountBlackjack`, `mountShooter`).
- **Scenes are classes**, one per file, filename = class name (`BlackjackScene.ts`, `ShooterScene.ts`, both extend `Phaser.Scene`). This is the one place where classes are the norm.
- **Pure logic is separate.** Rules, scoring and gesture math live in plain `.ts` files without engine imports, so they can be unit-tested. Scenes render and route input.
- **Tunables** (thresholds, timings, sizes, perk values, quality settings) are `UPPER_SNAKE_CASE` constants in the game's `config.ts`.
- **Boundaries:** no React, no `fetch`/`apiClient`, no navigation inside `games/`. Talk to the outside only through `MinigameOptions` (`character`, `dialogue`, `onFinish`). Only `components/common/MinigameHost.tsx` calls a mount function; only `games/shared/createGame.ts` creates a `Phaser.Game`.
- **Fake-depth budget (shooter):** fixed view, isometric sprites in one texture atlas, at most ~50 active sprites pooled in a `Group`, depth = scale + draw order + haze, no real-time lighting, glow only on `sharp`. Gameplay must also work in Phaser's Canvas fallback. See [docs/SHOOTER_CV.md](docs/SHOOTER_CV.md).
- **Assets:** import them (hashed URLs) and pass the URLs to Phaser's loader. The MediaPipe runtime files are the exception: they are served from `/static/mediapipe/` and `/static/models/`.
- **Cleanup:** `destroy()` must stop the game loop, timers, input listeners and the camera, and destroy the Phaser game (`game.destroy(true)` also removes the canvas). Calling it twice must be safe.

### Backend (Python / FastAPI)
- **PEP 8 naming:** `snake_case` functions/variables/modules, `PascalCase` classes, `UPPER_SNAKE_CASE` constants. The `XWHid` class names are an intentional exception (allowed in ruff config).
- **Type-hint every function** signature. Annotate route handlers with their return type (`-> Item`, `-> list[Item]`). FastAPI uses it as the response model, so no `response_model=` is needed.
- **Layering:** routers handle HTTP (status codes, `HTTPException`, request parsing); services handle data and logic, with no FastAPI imports and no knowledge of HTTP. Routers never touch storage directly.
- **One router module + one service module per feature**, same filename (`routers/widgets.py` ↔ `services/widgets.py`). Pure helper modules without a router (`services/endings.py`, `services/fallbacks.py`) are fine.
- **`def` vs `async def`:** use plain `def` unless the handler actually `await`s something (async HTTP client, async DB driver). FastAPI runs `def` handlers in a threadpool; a blocking call inside `async def` freezes the whole server. The Redis and OpenAI clients are synchronous, so handlers stay `def`.
- **Errors:** raise `HTTPException(status.HTTP_404_NOT_FOUND, "Widget not found")` with the named `status` constants and a human-readable `detail`. The frontend shows `detail` as the error message.
- **Validation** lives in the schema (`Field(min_length=1, max_length=200)`), not in handler `if`s.
- **Config:** add new settings as fields on `Settings` in `app/config.py` and document them in `.env.example`. Read them via `from app.config import settings`. Never use `os.environ` directly, and never commit secrets.
- **Imports:** absolute from the package root (`from app.schemas import Item`). Ruff sorts them.
- **Tests:** `tests/test_<feature>.py`, functions `test_<behaviour>`, using the `client` fixture and asserting on the JSON (camelCase) the frontend actually sees.
- **Formatting/linting:** `ruff format` + `ruff check` (line length 100). Run `make format`.

### Redis
- Only `app/db.py` creates the client; services call `db.get_redis()`. With an empty `REDIS_URL` it returns an in-process fakeredis (development and tests only).
- Values are Pydantic JSON (`model_dump_json()` / `Model.model_validate_json()`). Every key pattern is listed in [ARCHITECTURE.md → Redis data model](docs/ARCHITECTURE.md#redis-data-model); add new ones there in the same PR.
- Never publish the Redis port, and never point tests at a real Redis.

### OpenAI
- **Only `app/ai.py` imports `openai`.** Prompt text lives in `app/prompts.py`. Every AI feature has fallback content, is cached per run in Redis, and is reached only through `POST` endpoints.
- **`AI_MODE`** is `off` (default: no calls, fallback content), `fake` (canned content with a delay, no calls) or `live` (real calls). Develop UI in `fake`; use `live` only on purpose.
- **Keys** go in `OPENAI_API_KEYS` (comma-separated, used in order as a failover chain): `backend/.env` on your laptop, the server `.env` on the VM. Never in frontend code, git, issues, PRs, chat, screenshots or logs. Details: [ARCHITECTURE.md → Where the API keys live](docs/ARCHITECTURE.md#where-the-api-keys-live).

### Testing: zero credits
- **pytest** runs with fakeredis, `FakeAI` and the network blocked (pytest-socket, in `pyproject.toml`). A test that needs the real API is not a test; it is a manual check you announce to the team.
- **vitest** *(planned)* covers pure frontend logic only (`rules.ts`, `gesture.ts`, `run.ts`).
- **The smoke test only sends GETs**, so it can never trigger an OpenAI call.
- The full strategy is in [ARCHITECTURE.md → Testing strategy](docs/ARCHITECTURE.md#testing-strategy-zero-credits-by-default).

## Gotchas

- **The frontend build does not typecheck.** esbuild strips types without checking them. Run `npx tsc --noEmit` (included in `make check`).
- **Data in development resets on every backend reload** unless you run a real Redis: with an empty `REDIS_URL` the backend uses an in-process fakeredis, and `uvicorn --reload` restarts the process on every Python save. Use `make redis` and set `REDIS_URL` in `backend/.env` when you need persistence locally.
- **The production container runs one uvicorn worker.** Fine for us; with all state in Redis more workers would be safe, but in-process stores (the starter's `items` dict, fakeredis) are per process.
- **`/docs` (Swagger UI) is not exposed in production.**
- **You must refresh the browser** after a rebuild (no HMR). Responses are sent `Cache-Control: no-cache`, so a normal refresh is enough.
- **`/{page_name}` is a catch-all** for single-segment paths. `mount_frontend(app)` must stay the **last** line in `main.py`, after every router.
- **The page bundle is `type="module"`**, so top-level code runs after the DOM is parsed and `import`s are real ES modules. Don't use `require`.
- **`StrictMode` double-invokes effects in development.** Effects must be idempotent; `useApi` already handles cancellation. A minigame is mounted, destroyed and mounted again: `destroy()` must really release the Phaser game and the camera.
- **The camera only works on a secure origin:** `https://...` or `http://localhost`. `http://<vm-ip>:8000` will never get a camera; use HTTPS or an SSH tunnel to localhost (see ARCHITECTURE.md → Deployment).
- **Browsers block audio until the user clicks on that page.** A click on the previous page doesn't count after a full page load, so the graduation reveal starts with a click (**Open your diploma**) before the narration plays.
- **The hand model (`hand_landmarker.task`, 7.8 MB) must never be committed:** CI rejects files over 5 MB. The build downloads it into `frontend/public/models/` (git-ignored); if the download fails the build still succeeds and the shooter falls back to the mouse.
- **MediaPipe's `detectForVideo` is synchronous** and runs on the main thread, sharing the GPU with the Phaser scene. If frames drop, follow the performance ladder in SHOOTER_CV.md before anything clever.
- **Game FPS depends on the player's laptop, not on the VM.** WebGL and hand tracking run in the browser; the VM only serves files. Never judge game performance on the VM or in CI: neither has a GPU, so browsers there fall back to software rendering. Use the `?debug=1` overlay on real laptops with the camera on.
- **The shooter page downloads about 20 MB on its first visit** (MediaPipe wasm + hand model), much more than either engine. Responses are gzip-compressed (`main.py`); preloading it during the intro screen is the shooter track's job.
- **OpenAI calls never happen in tests or CI,** and only in development when you set `AI_MODE=live`. If you see real calls in a test run, stop and fix the test.
- Pages deleted from `src/pages/` are removed from `dist/` on the next rebuild. If the watcher acts strangely after big file moves, restart it (it wipes `dist/` on startup).
